# Security Policy

Code Archeologist is an early-stage development project. The local-development shell now has a pairing and cookie-session mechanism. It is **not** a secure repository importer or production application. Do not expose it on a network or use it for sensitive repositories.

To report a vulnerability, use the repository's **Report a vulnerability** / private GitHub Security Advisory channel where enabled. If it is unavailable, ask a maintainer to enable a private reporting channel without publicly disclosing exploit details.

## Security commitments

- Default analysis never executes imported source, MSBuild targets, dependency lifecycle scripts or tests.
- Localhost binding alone is not sufficient authorization. This development shell requires console pairing, authenticated session cookies, explicit Host/Origin checks and CSRF headers for unsafe methods. Local runtime checks for pairing passed in PR #2. Later milestones add authenticated local repository registration and explicit read-only snapshot capture. Registered sources are not executed, and file inventory classification reads only previously captured and hash-verified snapshot data; agent-command routes are still absent. This is not proof of a fully hardened browser security surface.
- Plugins are executable code; no assumed sandbox guarantee from in-process loading or process separation alone.
- No external LLM calls or source disclosure by default; no raw credentials in repository evidence or logs.
- Evidence provenance, safe snapshots, reversible vault reconciliation and user permissions are independent hard gates.

Workspace names, registered local directory paths and timestamps are stored in a local SQLite database, which is **not encrypted at rest** by Code Archeologist. Do not place passwords, tokens or other secrets in workspace or directory names; access depends on the local operating system account and file permissions. Security, workspace and repository-registration tests use disposable directories instead of production app data. Repository registration checks directories and Git marker presence only; it does not read source files, execute scripts or grant later ingestion permission. All future source acquisition must revalidate the path and protect against traversal, symlink changes and other filesystem races.

**Snapshot capture is explicitly invoked** in an authenticated workspace. It opens source bytes only for read-only copying, never runs Git, builds, package installers or code. It rejects traversal outside the selected root, tries to exclude symlinks and known secrets/binaries, imposes strict file/depth/byte caps, hashes included bytes, and revalidates the inventory before publishing. Saved snapshots are plaintext under local application data and are rehashed on manifest inspection. This is **not** a full secret detector, an operating-system sandbox or a race-free malicious-filesystem reader: a hostile concurrent local process can still potentially replace source paths between checks and file opens. Do not ingest adversarial or high-sensitivity material under stronger trust assumptions until restricted-handle acquisition and attack fixtures are implemented. See [Snapshot ADR](docs/decisions/0004-read-only-local-snapshot-foundation.md).

**C# syntax inspection** uses the pinned Roslyn syntax parser against already-captured and rehashed snapshot bytes. It does not create a compilation, invoke MSBuild, load project references, execute imported analyzers/source generators or run source code. Parsing does consume bounded memory/CPU and may report syntax errors; these observations do not establish resolved symbols or trusted behavior. Original source locations are not reopened during this endpoint. See [ADR 0006](docs/decisions/0006-roslyn-syntax-only.md).

**Provisional C# type links** use a synthetic Roslyn compilation assembled solely from already captured, SHA-256-verified C# text. The application does not emit or execute an assembly, load imported binaries, evaluate projects, restore packages or invoke source generators or third-party analyzers. Binding is an in-memory approximation with strict file/byte/reference limits, not a secure compiler sandbox or verified project dependency. See [ADR 0007](docs/decisions/0007-provisional-type-links.md).

**Static project-file inspection** parses saved, SHA-256-verified `.csproj` XML with DTD processing prohibited, no XML resolver, strict UTF-8, and limits on file/document size. It does not invoke MSBuild, restore packages or execute imported targets. File-to-project matches are only candidates: imports, properties, glob rules and conditions may alter actual compiler inputs. See [ADR 0008](docs/decisions/0008-static-project-membership.md).

**Project/type-link evidence reconciliation** invokes only the two existing snapshot-based analyzers, checks their matching snapshot identities/fingerprints and joins candidate source/target/project evidence in memory. It does not evaluate MSBuild or infer verified dependencies, and it inherits the upstream file/byte/usage caps, integrity rejection and DTD protections. No registered source path is reopened. See [ADR 0009](docs/decisions/0009-project-link-evidence-context.md).

**Evidence graph projection** does not evaluate projects or load source binaries. It joins only existing snapshot-based analyzers, verifies their consistent IDs/fingerprints, and emits bounded source/project/target/occurrence nodes and typed edges in memory. The browser diagram cannot convert candidate membership or synthetic Roslyn binding into verified dependencies. Node/edge caps fail closed without partial results; no SQLite graph persistence or external data disclosure is added. See [ADR 0010](docs/decisions/0010-first-evidence-graph.md).

**Syntax declaration graph expansion** uses only the already-restricted Roslyn syntax inspector on the same saved snapshot. Parsed classes, methods and properties are source-location evidence, not compiled or runtime symbols. Source identity is exact path/hash/span; reused referenced-declaration nodes never promote provisional Roslyn bindings. Existing analyzer resource caps and snapshot integrity checks continue to fail closed. See [ADR 0011](docs/decisions/0011-syntax-declarations-in-evidence-graph.md).

**Invocation-site evidence** is produced by bounded Roslyn syntax parsing over saved, verified .cs file copies only; source code and imported project/build tooling are never executed. Observed invocation expressions receive source path/hash/span anchors, and a containing method/constructor only when the nearest syntactic execution scope is unambiguous. Lambdas, local functions and unsupported scopes remain file-associated rather than being incorrectly attributed to an outer method. The graph never resolves a callee or claims a runtime call from the written invocation name; call-flood caps fail HTTP 413 rather than returning partial graphs. See [ADR 0012](docs/decisions/0012-csharp-invocation-sites.md).

**Source-only synthetic callee candidates** are computed from an in-memory, reference-free Roslyn compilation over verified saved C# source bytes. No build, source execution, imported analyzer, source generator, MSBuild evaluation, package restore or metadata import is added. A candidate edge requires one ordinary method symbol with exactly one source declaration and an exact matching captured syntax node; ambiguous/unsupported/missing targets remain unresolved, with no name-based fallback. The graph joins independently observed invocation sites by exact file/hash/span and fails 409 for a mismatch. Candidate callees are not compiler-verified project or runtime call edges. See [ADR 0013](docs/decisions/0013-provisional-callee-binding.md).

This policy distinguishes **implemented design controls** from unverified security guarantees. Do not expose the developer shell remotely; hosted TLS/auth, credential storage, broader browser-surface review and plugin sandboxing remain out of scope. Process console output and environment variables are trusted only to the extent the local operating-system account is trusted. See the design specification and phase-one acceptance checklist.
