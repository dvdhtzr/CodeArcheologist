# Code Archeologist

**Status: R1 product-completion integration in progress.** The application includes working local source snapshots, deterministic C# evidence analysis, one-hop provisional change-impact candidates, a genuine local MAF/Ollama multi-agent workflow, durable reports, host-written cautions, and a separate Mission Control frontend with live REST/SignalR. Agent assessments are not verified semantic facts. Mission Control is becoming the primary application while the original developer explorer remains a fallback. **This is not a packaged, hardened, or production-ready release.**

Code Archeologist aims to be a local-first, cross-platform software intelligence platform that analyzes one or more source repositories, constructs evidence-backed architecture and dependency models, supports adaptive multi-agent investigation, and preserves institutionally reviewed knowledge in an Obsidian-compatible vault.

The approved architectural baseline consists of [v0.1](docs/architecture/Code-Archeologist-v0.1.md), the [v0.2 technical design](docs/architecture/Code-Archeologist-v0.2.md), and the [subsequent owner-approval record](docs/decisions/0001-architecture-approval.md). Historical status wording in the original documents is preserved intentionally.

## Implemented capability history (some descriptions predate MAF)

The following list documents individual implementation slices. Later milestones supersede historical statements such as “no agents running yet.” For current user-facing operation, use Mission Control and the current API contracts.

- ASP.NET Core .NET 10 API bound only to loopback, exposing a public health endpoint and a protected local browser session.
- React + TypeScript development client with real API health, local browser pairing and a persistent workspace explorer.
- SQLite-backed workspace creation, listing and reopening across app restarts, protected by local pairing and CSRF checks.
- Authenticated registration of multiple existing local Git working trees or ordinary directories per workspace. Registration saves path metadata and does **not** read, build or execute source content.
- Separately authorized **Capture read-only snapshot** operation: includes eligible file bytes in application-managed storage, excludes known sensitive/vendor/binary paths, hashes included files, preserves prior revisions, and exposes an inspectable manifest. Capture never executes imported code or invokes Git/project builds.
- **Inspect source inventory** on a saved snapshot: a deterministic, read-only filename/extension classification of probable languages and file roles with exact manifest paths, SHA-256 anchors and exclusions. This is **not** a parser, graph, dependency finder, agent-based analysis or proof of functionality.
- **Inspect C# syntax** on a saved snapshot: a Roslyn parser finds namespace, type and member declarations and returns source spans, SHA-256 anchors and diagnostics. It parses copied, verified bytes only: no builds, semantic compilation, project loading, source generators or execution. This is not a call graph or symbol-resolution engine.
- **Inspect C# type links** on a saved snapshot: uses a bounded, reference-free Roslyn synthetic compilation to propose links between base-type clauses / explicit object creations and their source declarations. Every match is `provisional-local`, not a verified project dependency. Missing/ambiguous targets remain unresolved; no project evaluation or execution.
- **Inspect C# projects** on a saved snapshot: safely parse hash-verified `.csproj` XML and show candidate file membership from known SDK default patterns and literal unconditional Compile includes/removes. Unknown or conditional rules remain unresolved. This does **not** invoke MSBuild or prove which files actually compile.
- **Inspect link context** on a saved snapshot: cross-checks provisional Roslyn type references against candidate project-file membership and labels each relation shared, disjoint, unknown or unresolved. It displays file and project SHA-256 evidence, without upgrading candidate matches to verified compiler relationships.
- **Explore C# evidence graph** on a saved snapshot: navigable project/file/declaration/type-use/**invocation-site** nodes connected by typed, SHA-256-anchored evidence edges. In addition to observed method/constructor containment, an invocation may have a **provisional-local candidate-callee** link to a uniquely bound captured method under a reference-free synthetic Roslyn model. Missing/ambiguous targets remain unresolved, without guessed edges. Search, filters, neighborhood overview and one-hop traversal are available. This in-memory projection is **not** a verified project call graph or a persistent graph database.
- **Explore direct change-impact candidates** in that graph: select a captured method, search by name or path, and inspect *only direct incoming* provisional invocation-to-method candidates. Follow independently observed caller containment and source/project hash evidence; unresolved calls and transitive paths are explicitly excluded. An empty candidate list does **not** establish safety or absence of real callers.
- **Find HTTP attribute entry-point candidates** in the C# evidence graph: list source-annotated methods whose simple written attributes match common `HttpGet`/`HttpPost`/`HttpPut`/`HttpPatch`/`HttpDelete` spellings, with separately written route strings, saved SHA-256/source spans, and a link to each annotated method. **Not runtime-registered or effective URLs**; Minimal API call spellings are inventoried separately and other qualified/aliased attributes, dynamic routes and application configuration remain out of scope. See [ADR 0016](docs/decisions/0016-csharp-http-attribute-entrypoint-candidates.md).
- **Find Minimal API mapping candidates** in that graph: detect conventional member invocations `MapGet`/`MapPost`/`MapPut`/`MapPatch`/`MapDelete` from saved C# source, with literal or unresolved first route argument, non-binding handler syntax shape and exact SHA-256/span join to an existing invocation site. Same-named unrelated methods can produce false positives. **No ASP.NET runtime route, effective URL or handler binding is claimed.** See [ADR 0017](docs/decisions/0017-minimal-api-syntax-candidates.md).
- **Find DI registration candidates** in that graph: detect written `AddScoped`/`AddSingleton`/`AddTransient` calls from SHA-256-verified C# snapshot syntax, extract service/implementation type **spellings**, distinguish factory and unsupported overloads, and join each candidate to an exact observed invocation. This is **not** proof of a Microsoft DI registration, runtime service identity or effective lifetime. See [ADR 0018](docs/decisions/0018-csharp-di-registration-candidates.md).
- **Inspect agent-ready evidence package** on a captured HTTP attribute or Minimal API candidate: a typed, read-only, exact-snapshot response with bounded source excerpt, citation IDs, observed source containment, provisional direct callee relationships, snapshot provenance, and explicit unknowns. **Check example observed and candidate citation IDs** demonstrates independent reference validation without claiming free-text semantic truth. No LLM or MAF workflow is running yet. See [ADR 0019](docs/decisions/0019-agent-ready-snapshot-evidence-contracts.md).
- Local Windows PowerShell and Unix shell startup/build scripts with disposable security and workspace persistence tests.
- Safety, contribution, acceptance and architecture documentation.

**Remaining release scope:** unified visual architecture navigation, full functionality maps, cross-repository dependency analysis, complete vault/backup/restore workflow, plugins, sandboxed execution, vector retrieval, vault reconciliation, and packaged distribution. Production-grade hosted authentication and hostile-source ingestion are out of scope. The current MAF/Ollama worker and reports are implemented, but evaluations do not establish reliable semantic understanding. Source snapshots are user-authorized and must not be used for sensitive or adversarial repositories without additional hardening.

## Development

Requires a .NET 10 SDK and Node.js 22.12+ with npm **for working on the source**. Packaged releases are intended to eliminate those end-user prerequisites.

Windows: run scripts/check.ps1 then scripts/start.ps1.
macOS/Linux: run bash scripts/check.sh then bash scripts/start.sh.

**Primary UI:** Mission Control at http://127.0.0.1:5175/. Pair using the code printed by the startup script. Under **Live API**, choose or create a workspace, register a local folder, and capture or select a snapshot; then use **Architecture Explorer** for HTTP candidates, method declarations, and one-hop provisional impact. Select its **Evidence graph** tab and **Load saved evidence graph** to search evidence nodes, inspect source-defined edge statuses in a bounded neighborhood and open hash-verified source excerpts. This is not an independently confirmed dependency graph or exhaustive architecture map. The same scope is used for optional AI investigations. The **Snapshot coverage** tab independently displays saved file inventory, SHA-256 manifests, recorded exclusions, and filename-only classification limitations, even when the C# graph is unavailable. Interrupted runs expose **host-computed recovery eligibility**; eligible runs can be resumed only by an explicit, idempotent **Continue interrupted run** request, and the host rechecks checkpoints before admission. Session loss from any UI tab clears the connection and offers re-pairing. The current R2 Architecture Atlas provides a bounded saved-source C# evidence canvas, not an exhaustive or compiler-verified architecture. To use the legacy developer explorer, start its Vite app separately with `npm --prefix src/CodeArcheologist.Client run dev` on port 5174 while the API is running.

A new structured admission endpoint uses the existing fenced worker; SQLite v7 atomically persists question metadata and preserves old run/checkpoint behavior. See [R3 PR1 architecture and acceptance](docs/architecture/r3-investigation-context.md). The Atlas launch and adaptive retrieval are **not implemented in PR1**.

**R2 Atlas Polish & Performance (PR3):** The Atlas now has a wider, responsive investigative workspace, collapsible search, a keyboard-resizable evidence panel, camera-preserving navigation and Back, higher-contrast focus and reduced-motion support. Model-free 10k/16k stress contracts and an optional JSON timing benchmark accompany opt-in fingerprint-pinned curated-repository browser acceptance. Scope and truth claims are unchanged; see `docs/architecture/r2-atlas-polish-performance.md` for owner GREEN and visual walkthrough gates.

**R2 Evidence Navigation (PR2):** Selecting an Atlas edge now opens its full saved relationship evidence, exact source/target IDs, project-context candidates, and an inline re-verified source excerpt with focus-line highlighting. Source must match the selected snapshot, fingerprint, file SHA-256, and line before display. Use endpoint buttons and bounded in-memory Back history to follow only existing graph nodes; returning restores prior selection and expansion. See `docs/architecture/r2-evidence-navigation.md` for the acceptance gate and limits.

**R2 Architecture Atlas (PR1):** Mission Control's Architecture Explorer now starts on a **read-only, React Flow + Dagre Architecture Atlas**. It shows a bounded saved C# project/file overview, exact focused incoming/outgoing evidence relations, cross-graph node search, deliberately expandable neighborhoods, evidence-status legend, source inspection links, visible-versus-eligible counts, and an explicit 413 failure path. The diagram never invents architectural clusters, compiler-confirmed calls or dependencies. All existing deterministic explorer views remain accessible. See `docs/architecture/r2-atlas-foundation.md` for rendering limits and acceptance boundaries.

**R1 closeout:** PR3 integrates the operational features that the original developer explorer supported but the primary UI lacked: capture coverage and recorded exclusions, host-gated continuation of interrupted runs, and shared session-expiry handling. The historical legacy explorer remains a read-only advanced diagnostics fallback for specialized Roslyn/project and evidence-handle inspectors. See `docs/architecture/r1-closeout-gate.md` for R1 acceptance and deliberate R2 deferrals.

**Automated browser acceptance:** `scripts/check.ps1` / `scripts/check.sh` also run pinned Playwright headless Chromium checks covering real pairing, graph navigation, source inspection, impact navigation and snapshot switching against a disposable source/API database. The first run may download Chromium, but neither Ollama nor a personal workspace is needed. Stop dev servers before GREEN verification. See `src/CodeArcheologist.MissionControl/README.md` for standalone commands and failure traces.

**Local pairing:** the start script prints a new 32-character pairing code. Enter it in the browser to unlock the current process-scoped local session. The API uses an HttpOnly SameSite=Strict cookie, a server-side revocation list and a CSRF header for state-changing requests. Sessions expire after 30 minutes and are invalid after restarting the API. The code is shown only in local terminal output and must not be shared. The pairing code can be retried until the API stops, with temporary lockouts after repeated failures. Pairing is for localhost-only development, **not remote or multi-user access**.
Open http://127.0.0.1:5175/ ; the API is on http://127.0.0.1:5127/ and supports GET /api/v1/health.

The committed `package-lock.json` pins the frontend dependency graph; local verification uses `npm ci` to reproduce it. Previously successful Windows developer verification does not establish cross-platform packaging. GitHub CI is intentionally absent. The check scripts also run security and workspace integration tests against the trusted API with isolated, temporary SQLite databases. Stop the development server before running the check script because both use API port 5127. All verification outcomes must be documented.

### Local workspace data

Workspace metadata is stored in `workspaces.sqlite3` under the operating system's per-user local application data directory in a `CodeArcheologist` subfolder (normally `%LOCALAPPDATA%\\CodeArcheologist` on Windows). No database server, model or API key is required to create a named workspace. Workspace names are not filesystem paths. Tests use isolated temporary data directories and temporary repository fixtures; they do not alter your real workspaces or source repositories.

The API requires a paired local browser session for listing/reading workspaces, and a CSRF-protected UUID idempotency key for creation. It currently displays at most the 100 newest workspaces with an explicit count if more exist; pagination and backup/restore remain separate deliverables. Avoid recording secrets in workspace names. To register a source, open a workspace in the paired browser and enter the absolute path of an existing local directory. Registration checks and records the path, but does not scan or execute it. A directory with a `.git` marker is labelled as Git; other directories are labelled as local folders. Registrations persist through restarts. Symlink/junction roots, network paths, and filesystem roots are rejected in this first slice. Source locations are plaintext metadata; do not include secrets in their names. Inside a registered source, click **View snapshots** and then **Capture read-only snapshot** to explicitly copy and fingerprint eligible source files. Exclusions include Git metadata, known secret filenames, common binary extensions, vendor files and generated caches. **There is no general secret scanner.** Review source privacy before capturing: ordinary source files may contain confidential values. Captured bytes stay in the per-user local application data directory under `snapshots/<snapshot-id>`. The app does not run imported project files, restore dependencies, or interpret README instructions. Source capture has bounded file sizes and counts; rejected attempts do not publish partial snapshots. The displayed fingerprint is a **filesystem content manifest**, not a resolved Git commit. Known concurrent path/handle race limitations and recovery gaps are documented in [snapshot ADR 0004](docs/decisions/0004-read-only-local-snapshot-foundation.md).

For the first deterministic inventory, choose **Inspect source inventory** next to a saved snapshot. It reads only the stored and hash-verified snapshot, never the current source folder. Language and file-role labels are inferred from filenames, not from parsing code. See [ADR 0005](docs/decisions/0005-snapshot-file-inventory.md).

For written call expressions, open **Explore C# evidence graph** and filter by **Invocation sites (candidate or unresolved)**, or select a method declaration to see its directly contained invocation expressions. Containment edges are `observed-syntax`; an invocation may also have a `candidate-callee` edge labeled **`provisional-local`**, selected by a reference-free synthetic Roslyn compilation, never actual project-verified binding. Unresolved invocations have no guessed target. Calls in lambdas and local functions remain associated with their file rather than falsely attributed to an outer method. See [ADRs 0012](docs/decisions/0012-csharp-invocation-sites.md) and [0013](docs/decisions/0013-provisional-callee-binding.md).

For a source-only starting point for application operations, open **Explore C# evidence graph** and locate **Find HTTP attribute entry-point candidates**. Select a listed candidate to inspect its method node or jump to its one-hop impact review. The panel shows individual written HTTP/type/method route strings without claiming that the composed URL exists. A zero-candidate snapshot is not proof that the project has no HTTP entry points.

To inventory Minimal API-style mappings (including Code Archeologist's own `Program.cs`), open **Explore C# evidence graph** → **Find Minimal API mapping candidates**. Select an occurrence with **Inspect mapping and source invocation in graph** to jump directly to the selected evidence panel, with its saved invocation link, not merely update a node below the visible viewport. Existing captured snapshots can be reanalyzed without executing or modifying the registered source; only saved files are read. Empty results do not prove that no endpoints exist.

To inspect what our future agents are permitted to cite, open **Explore C# evidence graph** → **Find HTTP attribute entry-point candidates** or **Find Minimal API mapping candidates**, and click **Inspect agent-ready evidence package**. The panel displays saved source excerpt and citation IDs. **Check example observed and candidate citation IDs** validates their exact snapshot identity and evidence type, but is not semantic verification of a narrative claim. This is deterministic source-evidence plumbing only, not a model investigation.

For DI source evidence, open **Explore C# evidence graph** → **Find DI registration candidates**, then select **Inspect DI registration and source invocation in graph**. The graph shows written candidate type syntax, an explicitly unresolved factory/instance status where relevant, and a separate observed invocation relationship. Service registration and runtime resolution are **not** verified.

For a method change review, open **Explore C# evidence graph**, find **Explore direct change-impact candidates**, search or select a method, and inspect its source-observed potential call sites. The panel starts with an existing candidate-backed method when available; use **Review direct impact candidates** from the callee project-evidence finder to jump to a particular proposed target. Each result shows the observed caller or containing file, saved hashes, and the callee's provisional classification. A method with no incoming candidates is **not** proven unused; unresolved invocations, transitive callers and runtime effects remain unknown. See [ADR 0015](docs/decisions/0015-one-hop-provisional-change-impact.md).

On any `candidate-callee` edge, the graph now shows static **shared**, **disjoint** or **unknown** project candidates, along with source, target and shared `.csproj` candidates (project SHA-256, inclusion basis and unresolved-rule count). This helps assess the synthetic match but **never upgrades it to a real project-verified method dependency**. See [ADR 0014](docs/decisions/0014-callee-project-candidate-context.md). In the graph, use the **Find callee project evidence** panel and its **Filter callee project context** selector to find qualifying candidate links directly; expand **Show source, target and shared project evidence** on any listed candidate. The panel explicitly reports when a saved snapshot contains no provisional callee candidates, rather than asking you to hunt for a nonexistent link.

For syntax-observed declarations—including methods and properties that type links do not mention—filter the graph by **Parsed declarations (unreferenced)**. Existing referenced declaration nodes are reused when their saved source spans match. These nodes prove parsed source locations, not compiler symbols. See [ADR 0011](docs/decisions/0011-syntax-declarations-in-evidence-graph.md).

For the navigable evidence graph, click **Explore C# evidence graph** on a saved snapshot. Select a project, C# file or referenced declaration to follow candidate relationships with exact provenance and explicit uncertainty. See [ADR 0010](docs/decisions/0010-first-evidence-graph.md).

For evidence-qualified relationship context, click **Inspect link context** next to a saved snapshot. It combines the two prior analyses and distinguishes shared candidates, disjoint candidates, missing project candidates and unresolved targets; none imply a verified dependency. See [ADR 0009](docs/decisions/0009-project-link-evidence-context.md).

For candidate project memberships, click **Inspect C# projects** beside a saved snapshot. It shows file and project hashes, inferred membership reasons, and unresolved MSBuild rules. See [ADR 0008](docs/decisions/0008-static-project-membership.md).

For provisional links, click **Inspect C# type links** beside a saved snapshot; it displays source and candidate target anchors or unresolved references. See [ADR 0007](docs/decisions/0007-provisional-type-links.md). All source-local links are hypotheses until project membership, references and compiler settings can be established.

For the first parser-backed observations, click **Inspect C# syntax** next to a saved snapshot. Parse errors and configuration limits are shown explicitly; the initial request ceiling is 1,000 C# files / 32 MiB of C# text. See [ADR 0006](docs/decisions/0006-roslyn-syntax-only.md) for scope, source-span provenance and limitations.
